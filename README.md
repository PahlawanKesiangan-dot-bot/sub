# SubScope — hosting-ready Subfinder web app

SubScope is a responsive dark-mode web UI for ProjectDiscovery Subfinder. The included Docker image installs Subfinder, runs the Flask app with Gunicorn, and can be deployed to Render or any Docker-capable host.

**Use only with domains you own or have explicit permission to assess.** This wrapper uses passive enumeration only. It does not add brute-force enumeration, port scanning, active probing, or exploitation.

## Included

- Responsive dashboard with target domain input, result filtering, copy-all/copy-one, CSV export, timing and count.
- ProjectDiscovery Subfinder v2.17.0 included in the Docker image.
- Production login, secure session cookie, CSRF checks, login attempt throttling, per-client scan throttling and one-at-a-time scan execution.
- Dockerfile, Docker Compose, Render Blueprint, health check, and environment-variable configuration.
- Runs as a non-root user in the container.

## Recommended: deploy to Render

1. Extract the ZIP.
2. Create a new **private GitHub repository** and upload the *contents* of this folder (the Dockerfile and `render.yaml` must be at the repository root). Keep the repository private if you may later add provider configuration or internal project details.
3. Open the Render dashboard and select **New + → Blueprint**, then connect the repository.
4. Render reads `render.yaml`. Enter a unique username and a strong password when prompted for `APP_USERNAME` and `APP_PASSWORD`. Use at least 12 characters for the password. `SECRET_KEY` is generated by Render.
5. Create the Blueprint deployment, then open the service's generated `onrender.com` URL.

The first deploy builds the container, including Subfinder. `/healthz` is the health check route. On Render, `TRUST_PROXY=true` is set because the app is behind Render's trusted reverse proxy.

Render's free web services may sleep when idle, so the first request after idle can take longer. For a public production service, review current platform plan limits and consider a paid service if you need dependable response times.

## Deploy with Docker Compose

1. Install Docker Desktop or Docker Engine.
2. Copy `.env.example` to `.env`.
3. Edit `.env`, choosing a username, a unique password of at least 12 characters, and a random `SECRET_KEY` of at least 32 characters. Do not commit `.env` to Git.
4. Run:

   ```bash
   docker compose up --build -d
   ```

5. Open `http://localhost:10000`. If deploying to a public VPS, put it behind HTTPS using a trusted reverse proxy and keep the login enabled.

Generate a suitable secret with Python:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

## Hosting on another Docker platform

- Build from the included `Dockerfile`.
- Bind the service to the platform-provided `PORT` environment variable (the Docker command already does this; default is `10000`).
- Set `APP_ENV=production`, `APP_USERNAME`, `APP_PASSWORD` (12+ characters), and `SECRET_KEY` (32+ characters).
- Ensure HTTPS is enabled at the host/reverse proxy. `SESSION_COOKIE_SECURE` is enabled automatically in production.
- Set `TRUST_PROXY=true` **only** when a trusted reverse proxy overwrites `X-Forwarded-*` headers. For other hosting setups, leave it false unless the proxy behavior is understood.
- Do not deploy production with authentication disabled.

## Subfinder provider API keys

Subfinder has some passive data sources that work without credentials and others that require API keys. The app will run without provider keys, but results may be limited. Provider keys belong in Subfinder's provider configuration, not in HTML or JavaScript.

For Docker deployments, mount a provider config file into the container and set `SUBFINDER_PROVIDER_CONFIG` to its in-container path. Keep that file private and never commit it to Git. Refer to the official Subfinder documentation for the current provider-config format: https://docs.projectdiscovery.io/tools/subfinder/install

## Run locally without Docker (development only)

Requirements: Python 3.10+ and Subfinder installed on the machine.

```bash
python -m pip install -r requirements.txt
python app.py
```

Then open `http://127.0.0.1:5050`. This development mode binds to loopback and does not turn the Flask development server into a production server. Production uses the included Dockerfile and Gunicorn.

## Configuration

| Variable | Purpose |
|---|---|
| `APP_ENV` | Set `production` for hosted deployment; enables mandatory login and secure cookies. |
| `APP_USERNAME` | Login username. Required in production. |
| `APP_PASSWORD` | Login password, at least 12 characters. Required in production. |
| `SECRET_KEY` | Flask session signing key, at least 32 characters. Required in production. |
| `PORT` | Host-provided web port; default `10000` in Docker. |
| `SUBFINDER_BIN` | Subfinder executable path; defaults to `/usr/local/bin/subfinder` in Docker. |
| `SUBFINDER_PROVIDER_CONFIG` | Optional path to Subfinder's provider config file. |
| `TRUST_PROXY` | Trust one reverse proxy for forwarded IP/protocol/host headers; normally `true` on Render only. |

## Limits and notes

- Only one enumeration process runs at a time, each run has an 80-second hard timeout, and the same client is throttled between runs.
- A domain is validated and Subfinder output is filtered to the requested domain boundary.
- Results depend on public sources, API keys, and provider rate limits; no result list is guaranteed complete.
- This package is ready to deploy, but it is **not published to a public URL automatically**. You deploy it under your own hosting account using the steps above.
